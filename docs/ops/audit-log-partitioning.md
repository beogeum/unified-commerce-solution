# 감사로그 월 단위 파티셔닝 계획(M7, DLG-219)

지금은 적용하지 않는다(F9 메모: 운영 데이터가 1천만 행에 가까워질 때). 감사로그는 추가 전용(`forbid_mutation` 트리거)이고 보관이 원칙이라, 삭제가 아니라 **조회 성능·백업 크기** 문제를 푸는 것이 목적이다.

## 적용 시점(운영 현황에서 확인)
- `select count(*) from audit_log` 가 800만 행 이상이거나, 감사로그 조회(사용자·기간 필터) P95 가 1초를 넘을 때.

## 절차(전방 호환, 무중단에 가깝게)
1. 새 테이블 `audit_log_p` 를 `partition by range (occurred_at)` 로 만들고 같은 열·인덱스·RLS 정책·추가 전용 트리거를 붙인다. 월 파티션은 지난 24개월 + 다음 3개월을 미리 만든다.
2. 쓰기 전환: 감사 기록을 `audit_log_p` 로 쓰도록 배포(읽기는 두 테이블 `union all` 뷰 `audit_log_v`).
3. 과거 데이터 이관: 월 단위로 `insert into audit_log_p select … where occurred_at >= … and < …` (작은 배치, 업무 외 시간). 행 수·해시 대사.
4. 읽기 전환: 뷰를 `audit_log_p` 만 보도록 바꾸고, 구 테이블 이름 변경(`audit_log_legacy`) → 보관 확인 후 분리 보관.
5. 매월 1일 다음 달 파티션 생성 작업(스케줄)과 운영 현황 점검 항목 추가.

## 되돌리기
- 2단계 전까지는 새 테이블만 지우면 된다. 2단계 이후에는 뷰를 구 테이블로 되돌리고 새 테이블에 쌓인 행을 구 테이블로 옮긴다(추가 전용이므로 충돌 없음).
